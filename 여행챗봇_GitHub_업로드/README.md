# 여행 챗봇

LangSmith 연동은 [LANGSMITH_SETUP.md](LANGSMITH_SETUP.md)를 참고하세요.
두 대화 모드 모두 추적하며, 사이드바의 **LangSmith 추적 연결 → 연결 테스트**로 실제 쓰기 권한을 확인합니다.

## 5일차 시작 코드 적용

프로젝트를 연 뒤 **대화 방식 → 5일차 계획 에이전트**를 선택합니다.
예: “모레 경주에서 박물관 중심으로 하루 여행 계획을 만들어 줘.”
이어서 “방문은 두 곳만, 오후 1시부터 5시까지로 바꿔 줘.”라고 요청할 수 있습니다.
새 엔진은 하루 계획을 지원하며, 다일 여행은 **기존 여행 챗봇** 모드에서 계속 만듭니다.

제공된 `여행에이전트_시작코드`의 `agent.py`, `planner.py`, `trip_plan.py`를
`travel_agent/` 패키지에 통합했습니다. 이름이 같은 기존 모듈은 보존했습니다.
장소·날씨 호출은 기존 카카오·Open-Meteo 모듈로 연결하며, 지역 좌표는 행정구역 기준을 유지합니다.
제공 코드의 취향 자동 완화는 기존 요구에 맞게 제거했습니다. 실패 후 반복·추측한 필수 인자도 차단합니다.
새 계획 상태는 대화별로 SQLite에 보관되므로 다른 대화·프로젝트에 섞이지 않습니다.
실제 방문 데이터로 답변·현재 계획·별도 저장·캘린더 미리보기를 구성합니다.

LangSmith는 선택 사항입니다. `.env`에서 `LANGSMITH_TRACING=true`와
`LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`, 계정 리전에 맞는 `LANGSMITH_ENDPOINT`를 설정합니다.
미설정 시 추적은 꺼져 있습니다. 켜면 대화·도구 입력/결과가 LangSmith로 전송됩니다.
지원 endpoint는 `https://api.smith.langchain.com` 또는 `https://eu.api.smith.langchain.com`입니다.
`OPENAI_MODEL`을 설정하면 5일차 모드에 적용하고, 비워 두면 기존 `config.py`의 모델을 사용합니다.
테스트 상황은 `travel_agent/테스트상황.md`에 보관했습니다.

Python **3.12.3**, Streamlit, LangChain의 `langchain-openai` 통합 패키지와 OpenAI API를 사용합니다.
프로젝트별로 질문과 답변을 이 컴퓨터의 SQLite 데이터베이스에 자동 저장합니다.
저장한 대화를 선택해 다음 질문을 이어갈 수 있습니다.
장소 추천과 여행 계획은 카카오 장소 검색 도구의 결과를 바탕으로 작성합니다.
자동차 이동 시간·거리도 카카오 API로 조회하며, 일반 웹 검색은 사용하지 않습니다.

## 실행 방법 (Windows PowerShell)

1. Python 3.12.3을 설치한 뒤 이 폴더에서 버전을 확인하고 가상환경을 만듭니다.

   ```powershell
   py -3.12 --version
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe --version
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

   버전 출력이 `Python 3.12.3`인지 확인하세요. `.python-version`은 원하는 버전을 명시하며 Python을 자동으로 설치하지 않습니다.

2. 이 폴더의 `.env`에 `OPENAI_API_KEY` 값을 설정합니다. 이미 있는 `.env`는 그대로 사용합니다.
   자동차 길찾기를 사용하려면 같은 파일에 `KAKAO_REST_API_KEY`도 설정하세요.
   파일이 없을 때만 `.env.example`을 `.env`로 복사한 뒤 값을 채우세요.
   `.env.example`에는 변수 이름과 빈 값만 두세요. 실제 키 파일은 Git에서 제외됩니다.

3. 앱을 실행합니다.

   ```powershell
   $env:OPENBLAS_NUM_THREADS = '1'
   $env:OMP_NUM_THREADS = '1'
   .\.venv\Scripts\python.exe -m streamlit run app.py
   ```

   백그라운드 실행은 `.\start_chatbot.ps1`을 사용합니다. 메모리 오류를 줄이는 설정을 적용합니다.

4. 브라우저에서 http://localhost:8501 에 접속하여 첫 화면에서 프로젝트 이름을 입력하고
   **프로젝트 만들고 시작하기**를 누릅니다. 기존 프로젝트는 **프로젝트 열기**로 이어갑니다.
   프로젝트에 들어간 뒤 질문을 입력하고 Enter 또는 **답변 받기**를 누릅니다.
   대화 상단의 **← 시작 화면** 또는 사이드바의 **프로젝트 시작 화면**으로 첫 화면에 돌아올 수 있습니다.
   이후 '그 일정의 예산은?'처럼 이어서 질문할 수 있습니다.
   대화창은 카카오톡처럼 내 질문은 오른쪽 노란 말풍선, 답변은 왼쪽 흰 말풍선으로 표시합니다.
   새 메시지는 아래에 이어지고 대화창이 자동으로 스크롤됩니다. 입력창은 대화창 아래에 있습니다.
   왼쪽에서 프로젝트를 만들거나 저장된 대화를 선택할 수 있습니다.
   **새 대화**를 누르면 기존 대화를 보존하고 빈 대화를 시작합니다.
   왼쪽의 **대화 이름 → 이름 저장**으로 알아보기 쉬운 이름을 지정할 수 있습니다.
   **프로젝트 삭제**를 펼쳐 삭제 대상과 대화 수를 확인하고, 확인란을 선택한 뒤
   **프로젝트 삭제하기**를 누르면 프로젝트와 소속 대화가 함께 삭제됩니다.
   마지막 프로젝트를 삭제하면 빈 목록이 표시됩니다. 새 프로젝트를 만들어 다시 시작할 수 있습니다.
   삭제한 대화는 복원할 수 없습니다.
   종료하려면 터미널에서 `Ctrl+C`를 누릅니다.

## 파일과 설정

### 구글 캘린더에 직접 등록

저장한 여행 계획을 열고 **구글 캘린더에 바로 등록**을 펼칩니다.
미리보기의 날짜·시각·주소와 장소별 방문 시간(기본 90분)을 확인한 뒤,
**구글 계정 연결 → 등록 확인란 → 구글 캘린더에 등록** 순서로 사용합니다.
연결한 계정의 기본 캘린더에 한국 시간으로 등록하며, 운영시간과 실제 이동시간은 별도 확인해야 합니다.

최초 설정:

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 Google Calendar API를 사용 설정합니다.
2. Google Auth Platform에서 OAuth 동의 화면을 구성하고 테스트 상태라면 본인 계정을 테스트 사용자로 추가합니다.
3. OAuth 클라이언트를 **데스크톱 앱** 유형으로 만들고 JSON을 내려받습니다.
4. 프로젝트의 `.data/google_oauth_client.json`으로 저장합니다. 이 폴더는 Git에서 제외됩니다.
5. 앱의 **설정 다시 확인**을 누릅니다. 로컬 PC 기본 브라우저에서 직접 로그인·권한 승인을 완료합니다.

인증 토큰은 디스크나 대화 DB에 쓰지 않고 현재 Streamlit 세션 메모리에만 보관합니다.
이 기능은 사용자 PC에서 실행하는 로컬 앱용입니다. 원격 배포에는 웹 서버 OAuth 방식으로 변경해야 합니다.
권한은 본인 소유 캘린더의 일정 접근(`calendar.events.owned`)으로 제한합니다.
같은 생성 계획과 방문 항목에 고정 Google 이벤트 ID를 사용해 재등록·부분 실패 후 재시도 시 중복을 방지합니다.
구글 캘린더에서 수정·삭제된 동일 항목은 덮어쓰지 않고 확인을 요청합니다.
다른 실행에서 새로 만든 계획은 별개 일정입니다. 날짜가 같더라도 자동으로 같은 여행으로 병합하지 않습니다.
앱의 보관 사본 삭제는 구글 캘린더에 영향을 주지 않습니다.

참고: [Google Calendar Python 시작 안내](https://developers.google.com/workspace/calendar/api/quickstart/python),
[데스크톱 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app).

- `app.py`: 질문 입력 폼, 프로젝트·대화 선택, 새 대화, 이름 변경, 오류 안내
- `answer_view.py`: 답변 마크다운, 장소 목록 접기, 이동 시간 카드, 조회 근거 표시
- `planner.py`: 여행 조건 입력, 검색 후보 지도, 방문 순서 선택과 일정 작성
- `storage.py`: SQLite를 통한 프로젝트와 대화 자동 저장 및 복원
- `kakao_maps.py`: `search_places` 장소 검색 도구와 `get_driving_route` 자동차 길찾기 도구
- `chatbot.py`: 시스템 안내 + 이전 대화 + 현재 질문을 전달하는 LangChain 체인
- `config.py`: `MODEL_NAME`(기본값 `gpt-4o-mini`), 요청 제한 시간, `.env` 로딩
- `requirements.txt`: 필요한 라이브러리와 호환 버전 범위
- `.python-version`: Python 3.12.3 지정
- `.env.example`: 값이 없는 환경변수 예제
- `.gitignore`: `.env`, 가상환경, 캐시 등 제외
- `test_app.py`, `test_storage.py`: 실제 API 호출 없이 대화 전달, 저장·복원, 새 대화, 오류 처리 검증

모델을 변경하려면 `config.py`의 `MODEL_NAME`을 수정하고 앱을 다시 실행하세요.
해당 API 프로젝트에서 사용할 수 있는 모델이어야 합니다.
키는 실행 위치와 관계없이 `config.py` 옆의 `.env`에서 읽습니다.

시스템 프롬프트는 `chatbot.py`의 `SYSTEM_PROMPT`에 한국어로 작성되어 있습니다.
OpenAI Cookbook의 프롬프트 구성 예시를 참고해 역할과 목표, 대화 범위,
답변 지침, 정확성, 출력 형식, 독립적인 응답 예시로 구성했습니다.
이전 대화의 조건을 참고하되 사용자가 가장 최근에 변경한 조건을 우선합니다.
카카오에서 실제 조회한 시간·거리만 조회 결과로 안내합니다.
출발지나 도착지가 없으면 추가 질문을 하고, 여러 장소가 검색되면 정확한 위치를 확인합니다.
현재 출발 기준 국내 자동차 추천 경로를 지원하며 미래 출발 예측, 대중교통, 도보는 지원하지 않습니다.
예: '서울특별시청에서 서울역까지 차로 얼마나 걸려?'
장소 검색 예: '부산 기장에서 해산물을 먹고 바다를 보는 당일치기 코스 추천해 줘.'
모델은 지역·취향을 파악하고 `search_places`를 호출한 뒤 결과를 바탕으로 답변합니다.
첫 검색 후보가 3곳 이상이면 추가 검색 없이 답변합니다. 결과가 0건이면 핵심 조건을 유지해 한 번만 재검색합니다.
식당 검색은 음식점 분류(FD6)를 사용해 수산물 판매점 등과 구분합니다.
장소 검색은 한 질문당 최대 2회이며, 실제 검색된 식당·관광지의 주소와 좌표를 바탕으로 동선을 구성합니다.
같은 검색 인자를 반복하지 않으며 지역과 실내 조건은 유지합니다.
'후보가 없으면 다른 종류로'라는 요청이 있을 때만 장소 종류를 넓힙니다.
지역·실내 등 핵심 조건을 바꿔야 하거나 두 번째 검색에도 후보가 없으면 먼저 사용자에게 확인합니다.
별점·리뷰·영업시간·메뉴 가격은 장소 검색 API에 없으므로 확인된 정보처럼 답하지 않습니다.
지역이 없으면 추가 질문을 하고, 검색 결과가 없으면 검색어를 조정하거나 확인이 필요하다고 안내합니다.
카카오 키는 OpenAI 모델에 보내지 않고 서버의 카카오 인증 헤더에만 사용합니다.
답변마다 '카카오 API 실제 조회 완료', '카카오 경로 조회 미완료', '카카오 조회 안 함'을 구분합니다.
조회 성공 시 확인한 출발·도착 장소, 시간·거리, 조회 시각, 카카오맵 장소 링크를 별도 영역에 표시합니다.
장소 검색에는 검색어·조회 시각·실제 반환된 장소 목록과 각 장소의 카카오맵 링크가 표시됩니다.
'조회 근거 보기'에서 인증 정보가 제외된 조회 기록과 카카오 요청 ID를 확인할 수 있습니다.
이 기록은 대화와 함께 저장되며 이전 답변을 다시 열어도 확인할 수 있습니다.
기록 기능 추가 전의 답변은 조회 여부를 확인할 수 없다고 표시합니다.
답변은 요약과 짧은 제목·일정 표로 구성하고, 원본 조회 정보와 중복되는 긴 내용은 본문에서 분리합니다.
검색된 장소 목록과 상세 근거는 펼쳐서 확인할 수 있습니다.

## 조건과 지도로 여행 계획 만들기

1. 프로젝트를 열고 **1 · 여행 조건**에서 지역, 날짜, 인원, 전체 예산, 교통수단, 출발지와 취향을 입력합니다.
2. **조건 저장하고 장소 찾기**를 누르면 저장한 조건에 맞춰 카카오 장소 후보를 검색합니다.
3. **2 · 지도와 방문 순서**에서 후보 위치를 보고 방문할 장소를 순서대로 선택합니다.
4. **선택한 동선으로 일정 만들기**를 누르면 조건과 선택한 순서를 반영해 날짜별 일정을 작성합니다.

조건과 선택 순서는 프로젝트에 저장되며, 추가 질문에도 반영됩니다. 예산은 전체 인원 합계이며 0은 미정입니다.
지도 연결선은 선택한 방문 순서를 잇는 직선 미리보기로, 실제 도로 경로나 최적 경로가 아닙니다.
자동차 이동 시간은 별도로 카카오 길찾기 도구로 조회할 수 있습니다. 미래 출발 시각의 예측은 지원하지 않습니다.
지도 배경은 CARTO, 장소 좌표는 카카오 검색 결과를 사용합니다.

## 장소 질문 처리

- 지역과 장소 종류·방문 조건을 포함한 질문은 카카오 장소 검색 도구를 호출하고 결과를 모델에 전달합니다.
- 장소 검색에는 날짜가 필요하지 않습니다. 조건 화면에서도 날짜는 선택 사항이며 미선택 시 저장하지 않습니다.
- 지역이 없으면 지역만 묻고 다음 입력을 기다립니다. 모델이 임의로 만든 지역은 검색에 사용하지 않으며, 미실행 검색은 실행 기록에 남기지 않습니다.
- 지역만 답해도 이전 사용자 대화의 동행인·실내 조건을 함께 참고합니다. 예: “부모님과 갈 실내 장소” → “경주요”.
- 인증·권한 오류와 사용 한도 초과는 결과 0건과 구분하고 즉시 중단합니다. 실패 안내를 모델이 성공한 조회나 임의 장소 추천으로 바꾸지 않습니다.
- 한 번의 답변에서 도구는 최대 4회, 모델은 최종 답변 생성을 포함해 최대 6회 호출합니다. 장소 검색은 기존의 최대 2회 규칙을 우선 적용합니다.
- 호출 한도에 도달하면 검색을 멈추고 조건 조정 여부를 묻습니다. API 오류 안내와 기록에는 키나 서버 오류 원문을 포함하지 않습니다.
- 단순 장소 안내는 조회된 장소명·주소·지도 링크 중심으로 표시합니다. 일정 요청에는 기존 일정 작성 흐름을 사용합니다.
- 단순 인사는 장소 도구를 호출하지 않고 응답합니다.
- 답변의 **도구 실행 기록**에서 도구명, 실제 전달한 검색 인자, status를 확인할 수 있습니다. API 키는 기록하지 않습니다.
- 기존 프로젝트·대화 기억·카카오맵 링크·방문 순서 기능은 유지합니다.
카카오 장소 검색과 카카오모빌리티 길찾기의 이용 권한·한도는 각각 확인해야 합니다.

대화는 프로젝트 폴더의 `.data/conversations.sqlite3`에 저장합니다.
새로고침하거나 서버를 다시 실행해도 왼쪽에서 저장된 대화를 선택해 이어갈 수 있습니다.
현재 컴퓨터에서 사용하는 여행 챗봇 자체의 프로젝트이며 Codex 계정과 동기화되지는 않습니다.
로그인 기능은 없으므로 이 로컬 앱을 여는 사람은 같은 저장 목록을 사용합니다.
기능 적용 전에 현재 세션에 남아 있던 대화는 처음 실행 시 '내 여행' 프로젝트로 가져옵니다.
이미 세션이 사라진 과거 대화는 복원할 수 없습니다.
데이터를 백업하려면 앱을 종료하고 `.data` 폴더를 복사하세요.
`.data/`는 Git에서 제외되며 API 키는 데이터베이스에 저장하지 않습니다.
성공한 질문·답변 쌍만 기록하며 빈 입력이나 실패한 요청은 기억에 추가하지 않습니다.

빈 입력과 공백 입력에는 API를 호출하지 않습니다.
오류는 고정된 안내 문구만 표시하며 예외 원문과 키를 출력하지 않습니다.
API 요청에는 비용이 발생할 수 있습니다. 실시간 여행 정보는 공식 안내를 확인하세요.

## 검증

### 검사를 거친 여행 계획 만들기

1. 여행 조건에 지역·시작일·종료일·취향을 저장하고 장소를 찾습니다.
2. **지도와 방문 순서**에서 방문할 장소를 고르거나, 선택하지 않고 현재 지역·날짜의 전체 후보를 사용합니다.
3. **취향·날씨로 방문 순서와 여행 계획 추천**을 누르면 실제 장소 기록과 새 Open-Meteo 예보를 검사합니다. 직접 고른 순서를 유지하려면 **선택한 동선으로 일정 만들기**를 누르세요.
4. 성공 여부·지역·날짜 검사를 통과한 근거로 시간대·방문 순서·옷차림·준비물을 제안하며, 제안된 순서는 지도와 프로젝트에 저장합니다.

장소 조회 자체는 운영일·예약·가격을 제공하지 않습니다. 날짜 정보가 없는 기존 장소 조회는 날짜와 무관한 장소 정보로 사용하되, 특정 여행 날짜가 저장된 기록은 그 범위가 현재 계획과 같아야 합니다. 다른 지역·날짜 또는 실패 자료는 제외하고 **확인 필요**로 표시합니다. 날씨만 실패하면 장소를 근거로 부분 계획을 만들며 날씨에 따른 준비물을 지어내지 않습니다. 통과한 장소가 하나도 없으면 방문 순서 작성을 보류합니다. 검사 표는 실행 기록에서 확인할 수 있습니다.

방문 시간대와 직선거리는 계획 제안이며 실제 도로 이동 시간이나 운영시간이 아닙니다. 한 번에 최대 31일·장소 12곳을 제안하고, 실제 도구 호출은 기존 한도 4회 안에서 처리합니다.

### 실행 기록으로 검색 과정 확인

- 새 답변 아래 **실행 기록**을 펼치면 도구 이름·인자·상태·반환 후보와 다음 처리, 재검색 이유를 순서대로 확인할 수 있습니다.
- 제목에 실제 도구 호출 횟수와 모델 호출 횟수·한도가 표시됩니다. 시작·종료 시각, 소요 시간, 종료 이유도 저장합니다.
- **실행 기록 비교**에서 같은 프로젝트의 실행 두 개를 골라 나란히 비교하세요. 동일 질문의 1회 검색과 재검색 실행을 비교하면 검색어 변경과 종료 이유를 확인할 수 있습니다.
- 마지막 성공 조회 결과를 답변 근거로 표시하며 단순 장소 안내는 그 결과의 장소명·주소·링크로 구성합니다.
- 실행 기록은 프로젝트 데이터베이스에 저장되어 재접속 후에도 열 수 있고 JSON으로 내려받을 수 있습니다. 모델 호출 실패도 안전한 종료 사유를 남깁니다.
- 이전 버전의 답변에 새 상세 기록을 만들어 붙이지 않습니다. 모델의 내부 생각·프롬프트 전문·API 키·예외 원문은 기록하지 않습니다.

### Open-Meteo 날씨와 준비물

- 장소 추천이 성공하면 여행 날짜로 **장소 추천 → 지역 날씨 → 옷차림 → 챙길 아이템**을 자동 안내합니다. 별도로 날씨를 다시 물을 필요가 없습니다. 날짜가 없으면 장소 추천을 먼저 보여주고 방문 날짜만 물으며, 예보 범위 밖이거나 조회가 실패해도 확인한 장소 추천은 유지합니다.
- 추천 요청의 첫 단계는 장소 검색 도구를 필수로 선택합니다. 모델이 검색을 건너뛰고 일정 글만 쓰면 그 답변을 차단합니다. 사용자가 종류를 지정하지 않은 여행 추천에 모델이 임의로 붙인 분류 필터를 적용하지 않으며, 박물관 등 장소 종류로 실내 조건을 유지할 수 있을 때는 검색어의 불필요한 '실내' 단어를 제거합니다.
- 자동 조회도 한 실행의 도구 4회 한도를 지킵니다. 첫 장소 검색이 0건이면 재검색 1회 후 지역 대표 좌표·예보를 조회하여 총 4회 이내로 마칩니다.

- “경주 날씨 알려줘”처럼 **지역 날씨만** 물으면 추천 장소와 관계없이 카카오 주소 검색으로 행정구역 대표 좌표를 구하고 Open-Meteo 예보를 안내합니다. 날짜가 없으면 오늘 예보를 사용합니다. 지역 대표 지점 기준이므로 지역 안에서도 날씨 차이가 있을 수 있습니다.
- “경주 내일 날씨”는 내일의 지역 예보를, “선택한 장소의 날씨와 준비물”은 기존처럼 개별 장소 좌표와 여행 날짜를 사용합니다. 지역이 없으면 지역만 묻고 기다리며, 같은 이름의 지역이 여러 곳이면 시·도 확인을 요청합니다.
- “이번주 토요일 부산 날씨”처럼 주차·요일을 지정할 수 있습니다. 주는 월요일부터 일요일 기준이며, 이번 주·다음 주·다다음 주·주말과 상대 날짜(3일 뒤 등)를 해석할 때 사용한 표현을 지역명에서 함께 제거합니다. 연말에도 실제 달력 날짜로 계산하며, 이미 지난 날짜를 임의로 다음 주로 옮기지 않습니다.
- 지역 날씨에도 **외출·여행 옷차림**과 **챙길 준비물**을 함께 표시합니다. 실제 최저·최고 기온과 강수·바람·자외선에 따라 날짜별로 추천하며, 기온 자료가 없으면 옷 두께를 추측하지 않습니다.
- “그날 옷은 뭐 입어?”처럼 이어서 물으면 직전 예보의 지역과 날짜를 유지하고 예보를 새로 조회합니다.
- “그럼 이날 날씨는 어때?”처럼 여행 계획 뒤에 이어서 물으면 같은 대화의 최신 여행 지역·날짜를 우선 사용합니다. “11월 1일에 1박 2일 경주 여행”은 11월 1~2일 경주로 연결하며, 과거의 실패한 지역 검색이나 더 오래된 다른 여행의 예보는 이어받지 않습니다.

- 질문 예: “경주 2026-10-21 ~ 2026-10-23 날씨와 준비물 알려줘”, “내일 준비물은?”
- 지도에서 방문 장소를 선택하고 **선택한 장소의 날씨와 준비물 확인**을 누를 수도 있습니다. 저장한 여행 날짜를 사용하며, 날짜가 없으면 먼저 묻습니다.
- 카카오 검색 결과의 `y`를 위도, `x`를 경도로 사용합니다. 모델이 좌표를 생성하지 않습니다. 선택 장소가 없으면 먼저 실제 장소를 검색해 좌표를 확보합니다.
- 여러 장소는 한 번의 Open-Meteo 요청으로 조회합니다. 날씨도 도구 4회 한도와 실행 기록에 포함합니다. 단순 준비물 안내는 예보를 근거로 코드에서 구성합니다.
- 여행 날짜 전체가 오늘부터 15일 뒤까지인 최대 16일 예보 범위 안에 있어야 합니다. 과거·범위 밖 날짜는 조회하지 않으며 현재 날씨로 대신하지 않습니다. 날짜 기준은 한국 시간입니다.
- 날짜별 날씨·최저/최고 기온·강수확률·강수량을 답변으로 표시하고 바람·자외선·원본 조회 근거는 답변 아래 **날씨 조회 근거**에서 확인할 수 있습니다.
- 준비물 기준: 강수량이 0보다 크거나 강수확률이 40% 이상이면 우천 준비, 최저 10°C 이하면 보온, 최고 28°C 이상이면 더위 대비, 일교차 10°C 이상이면 겹쳐 입을 옷, 바람 8m/s 이상이면 바람막이, UV 6 이상이면 햇빛 대비를 제안합니다. 이 수치는 앱의 준비물 제안 기준이며 기상 특보 기준이 아닙니다.
- API가 반환하지 않은 값은 “정보 없음”으로 표시하고 준비물 판단에서 제외합니다. 인증·한도·네트워크·응답 오류는 예외 원문을 보여주거나 반복 호출하지 않습니다.
- 날짜와 선택 장소가 있는 일정 요청에는 실제 예보를 모델에도 전달하여 일정을 작성합니다. 이미 검색된 장소의 좌표는 재사용하되 날씨 예보는 매번 새로 조회합니다.
- 현재 공개 Forecast API를 사용하며 추가 API 키 설정은 없습니다. [Open-Meteo 공식 문서](https://open-meteo.com/en/docs)를 기준으로 구현했습니다.
