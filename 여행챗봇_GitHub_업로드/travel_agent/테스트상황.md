# LangSmith 강사 제공 공통 테스트 상황

학생이 테스트 상황을 새로 설계하는 것을 필수로 하지 않습니다. 강사가 아래 상황과 기대 동작을 보여주고 학생은 직접 자기 앱에 입력하여 Trace와 실제 결과를 확인합니다. 수정 요청은 학생이 직접 작성합니다.

| ID | 사전 상태 | 테스트 입력 | 기대 동작·확인 근거 |
|---|---|---|---|
| T01 | 새 대화, 키·추적 연결 완료 | 모레 경주에서 박물관 중심으로 하루 여행 계획을 만들어 줘. | 지역·날짜·취향이 도구 입력에 반영. 장소·날씨 조회 결과를 근거로 계획 작성. 장소명·주소·출처와 제안 시간/순서 구별. 없는 영업시간·가격을 지어내지 않음. |
| T02 | T01 직후 같은 대화 | 방문은 두 곳만, 오후 1시부터 5시까지로 바꿔 줘. | 경주·날짜·박물관 조건 유지, 방문 수 2곳·13~17시 반영. 답변과 현재 계획 일치. 재검색 필요 여부는 구현에 따라 판단하고 불필요한 반복을 관찰. |
| T03 | 새 대화로 초기화 | 여행 계획을 만들어 줘. | 지역·날짜를 되묻고 추측으로 여행 계획을 확정하지 않음. 도구 호출 유무·인자·차단 결과를 확인. |

강사는 실행일 기준 모레의 절대 날짜를 함께 제시합니다. 전후 비교에서는 그 날짜를 고정합니다. T02는 T01부터 동일 순서로 재현합니다. 장소명·날씨 숫자는 고정 정답이 아닙니다. 실제 조회 근거·조건 준수로 판단합니다.

진행: 상황/기대 결과 확인 → 직접 채팅 입력 → Trace 선택 → 입력·도구 이름/인자/응답·최종 출력·오류/시간 관찰 → 판정/근거 기록 → 문제 하나 수정 → 동일 초기 상태·질문·날짜·모델로 재테스트. 오류가 없으면 억지로 수정하지 말고 통과 근거를 기록합니다.

학생 작성 칸: 실제 답변 요약 / 실행 링크·ID / 도구 근거 / 기대 동작 대비 판정과 이유 / 발견한 문제 / 직접 작성한 수정 요청 / 재테스트 결과.
실제 서비스 호출·Trace 전송은 이번 준비 작업에서 실행하지 않았습니다. 과거 키 인증 HTTP 200을 Trace 성공 증거로 사용하지 않습니다. Cloud 실제 배포·학생 PC 검증은 생략합니다.
